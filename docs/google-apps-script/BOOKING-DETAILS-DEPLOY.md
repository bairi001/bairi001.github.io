# 预约选择传递升级：部署与验收

日期：2026-09-26。网站基线：352a88d5e2b74d93aee3eec166148d1b46ec8956。

## 已修复的代码路径

旧版网页 POST 没有附加项目和指名；WhatsApp 有。前端提交身份、后端五分钟去重也没有比较这些选择。新版网页 POST 同时发送 addons、nomination、sameRoomRequested、treatmentMinutes，并在旧后端已支持的 note 中保留简短选择摘要。姓名、电话、邮件和备注不得发送给 GA4。

前端不会截断客人备注或已选项目。为兼容现行 300 字符 note 接口，组合内容超限时明确提示缩短备注或改用 WhatsApp。可选的入口归因只在有余量时写入 note，不得挤掉预约信息。

## 发布顺序

1. 读取目前实际部署的预约 Google Apps Script 源码，与此目录 Code.gs 比较。仓库源码不证明线上部署版本；不得覆盖脚本中仓库没有的有效修改。
2. 保留现有 Script Properties、台账和部署 ID。记录当前部署版本，备份台账。不新建空台账，不变更接收邮箱。
3. 合并 Code.gs 的预约选择字段及去重修改，更新原 Web 应用到新版本，保留原 /exec 地址。健康检查应显示 shinyuuan-booking、version 3。
4. 原台账前 18 列保持原位。升级在第 19—22 列追加 addons_json、nomination_json、same_room_requested、treatment_minutes。若这些位置已有其他业务列，先调整列映射，不强行覆盖。旧记录保留。
5. 发布官网前端版本。四语内容可以独立发布；预约后端修复只有完成第 3 步才生效。
6. 经店主批准后，用明确标注的测试申请验证线上邮件及台账。不要用真实客人的信息测试，不把测试计入订单。

## 线上验收清单

- 日、英、中、韩各一份：基础课程、热石 20 分钟、指名、2 名同室需求在网页请求、店铺通知、台账中一致。
- 同室值只表示“提出需求”，不能当作“已确认”。人工回复必须明确同室是否成立。
- 热石 20 分钟增加 2,000 日元和 20 分钟；10 分钟增加 1,000 日元。两种时长不能同时选。没有“只加热石 500 日元”项目。
- 汉方油仅在芳疗类课程可选，汉方足膏仅在含足底的课程可选；各 500 日元。切换到不适用课程时清除该项。
- 人数从 2 改为 1 或 3/4+，同室选择被清除；再改回 2 不自动恢复勾选。
- 原样重试保持 submissionId；选择、备注、指名改变后使用新的提交标识。后端不得把不同选择吞为重复。
- 提交成功后再次点击不得重复发送。超时/未知结果不得被记为成功；保留现有 unknown 提示和人工联系方式。
- 邮件失败时仍有台账记录，店内需查看 mail_status，不把“申请已收到”当作“客人收到确认”。现行脚本发送的是店铺通知，不是客人的自动确认邮件。
- 多人预约各人的项目和开始时间由店铺核对，不简单把所有选项乘人数。足底排班另外预留泡脚 3—5 分钟以及准备时间。

## 尚未解决的经营问题

本次没有连接 HPB 实时库存，没有自动锁定员工或双人间，也没有声称网页显示的是实时空位。跨渠道撞单仍需要统一排班和人工确认；这应继续列为 P0。

## 回退

保留旧部署版本和本次 PR 的基线。回退官网时保留新增台账列和已有记录；不要删除客人申请。Apps Script 回退到已记录版本后再验证基础申请通路。前端兼容摘要有助于保留选择，但不能替代新版后端的去重修复。
